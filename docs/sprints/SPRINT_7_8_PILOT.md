# Sprint 7–8 — Hardening and Content Pilot

## Objective
Validate operational reliability and editorial performance with real but responsibly sourced content.

## Tasks
- Run full E2E regression.
- Test backup and restore.
- Review authentication, secrets, logs, uploads, and rate limits.
- Fix critical UX and reliability issues.
- Produce 10–15 pilot pieces in Sprint 7 if editorially approved.
- Aim for 30 total published pieces by the end of Sprint 8 if capacity and quality allow.
- Record per-post topic, hook, format, duration, views, average watch time, completion, shares, saves, and follows.
- Compare results by cohort; avoid overfitting to a single post.
- Version prompt and playbook changes.
- Write a pilot report and V1.1 backlog.

## Pilot report template
1. Number of sources captured.
2. Number of trends selected.
3. Number of briefs/scripts generated.
4. Human approval rate and common edit reasons.
5. Median production time.
6. Cost per produced/published asset.
7. Performance by topic, hook, format, duration.
8. Safety incidents/corrections/takedowns.
9. What to stop, continue, and test next.
10. V1.1 priorities.
